# Data provenance, composition and licensing

**Last verified:** 12 November 2026, against the files listed below.
**Purpose of this page:** answer “what is this data, where did it come from, what may I
claim from it?” without ambiguity.

## 1. What is in the repository

| File | Rows | What it is |
|---|---|---|
| `data/synthetic/complaints_15k.csv` | 15,000 | Canonical development corpus, seed 42, generator v1.1.0 |
| `data/synthetic/complaints_2k_eval.csv` | 2,000 | Held-out evaluation corpus, separate seed, never used for tuning |
| `data/synthetic/ground_truth_15k.csv` | 15,000 | Labels for the development corpus (evaluation only) |
| `data/synthetic/ground_truth_2k_eval.csv` | 2,000 | Labels for the held-out corpus |
| `data/synthetic/complaints_demo.csv` | small | Seeded file used by the interface demo |
| `data/source_manifest.csv` | — | Per-file provenance: publisher, basis, date, rows, transformations |
| `data/geography/jharkhand_state.geojson` | 1 feature | State outline only, not the 24-district file a choropleth needs |
| `data/processed/` | generated | Output of `scripts/prepare_dataset.py`; gitignored |

The canonical CSV has a header plus exactly 15,000 data rows; the held-out file has a
header plus 2,000. Ground truth lives in sidecars keyed by `complaint_id` and is never
merged into the canonical files.

## 2. Measured composition

- **Districts:** all 24 names defined in `src/data/complaints.py` appear in the corpus.
- **Domains:** 12 (`Water Supply`, `Sanitation & Waste`, `Roads & Connectivity`,
  `Electricity`, `Healthcare`, `Education`, `Food & PDS`, `Land & Revenue`,
  `Welfare & Pensions`, `Employment & Livelihoods`, `Agriculture & Irrigation`,
  `Safety & Environment`).
- **Sub-issues:** 71, as counted from `ground_truth_15k.csv`.
- **Languages:** `hi`, `en` and `hinglish`; the generator targets 45/35/20 but the
  exact realised proportions depend on the seed and are recorded in the file itself.
- **Duplicates:** 1,500 injected (10% of the corpus) — 1,200 near-duplicates that are
  true paraphrases of their source, 300 exact duplicates. Every injected row carries
  `is_duplicate`, `duplicate_kind`, `duplicate_of` and a `duplicate_group_id`.
- **Dates:** 18 modelled months with monsoon and month-end seasonality. This is a
  generator design choice, not a measured property of real complaints.
- **Severity / affected population:** weighted per sub-issue and log-normal
  respectively, both generator assumptions.

Counts can be re-derived from the files:

```bash
wc -l data/synthetic/complaints_15k.csv data/synthetic/complaints_2k_eval.csv
awk -F, 'NR>1 {n++; if ($6=="1") {d++; if ($7=="near") near++; if ($7=="exact") exact++}} \
  END {print "rows="n, "duplicates="d, "near="near, "exact="exact}' \
  data/synthetic/ground_truth_15k.csv
awk -F, 'NR>1 {i[$3]=1} END {print "sub_issues="length(i)}' \
  data/synthetic/ground_truth_15k.csv
```

## 3. What this data is not

- **Not real complaints.** Every row is generated by
  `src/data/synthetic_generator.py` v1.1.0. No row describes a real person or event.
- **Not a sample of Jharkhand.** District volumes, dates and severities are
  generator parameters; they support interface and pipeline development only.
- **No real-text benchmark is included.** The plan's CC0 Kaggle citizen-grievance
  dataset has not been downloaded, so `docs/RESULTS.md` reports no real-text result.
- **No official extract has been granted.** The PGMS/CPGRAMS outreach described in
  `docs/MASTER_PLAN.md` §4 produced no data; nothing here is derived from a portal.

A synthetic row can never carry `verification_status=verified`: the canonical
validator rejects that combination rather than coercing it.

## 4. Canonical schema and validation

Every dataset — synthetic, benchmark or future official extract — must validate
against `src/data/complaints.py`. The canonical columns are exactly:

```
complaint_id, complaint_text, district, block, complaint_date, language,
severity, affected_population, source_type, verification_status
```

- `complaint_date` is ISO `YYYY-MM-DD`.
- `severity` ∈ `unknown | low | medium | high | critical`.
- `source_type` ∈ `public_dataset | consent_survey | synthetic | other`.
- Validation rejects unknown districts, invented severities, empty text and duplicate
  `complaint_id` values instead of repairing them silently.
- Ground truth columns (`domain`, `sub_issue`, `true_severity`, `duplicate_group_id`,
  `is_duplicate`, `duplicate_kind`, `duplicate_of`) exist only in the sidecars, so
  production code never reads labels.

## 5. PII and ethics

- The synthetic corpus contains no personal data by construction; it is generated from
  templates and slot fillers, not collected from people.
- The **bulk ingestion path** (`src/data/ingest.py`) strips phone numbers, emails and
  ID-number patterns before writing canonical rows, and requires a source type.
- The **API path is different**: `POST /api/v1/complaints` stores the submitted text as
  written. The form warns citizens not to include names, phone numbers or ID numbers,
  but no automatic scrubber runs on submissions. This is a known gap, not a claim of
  anonymisation. Brief evidence quotes therefore come from whatever text was submitted
  to that local database, which in the demo is text you typed yourself.
- The interface never shows account usernames alongside public evidence quotes.

|---|---|

| `jharkhand_state.geojson` | OpenStreetMap relation 1960191, **ODbL 1.0** (recorded in the file's properties) |

If a real extract is granted later, ingest it with `src/data/ingest.py`, add a row to
`data/source_manifest.csv` with licence/consent basis and retrieval date, and label it
`public_dataset` or the appropriate source type. Never relabel synthetic rows.

## 7. Regeneration

```bash
python scripts/generate_corpus.py --records 15000 --eval-records 2000 --seed 42
python scripts/prepare_dataset.py --input data/synthetic/complaints_15k.csv \
  --output data/processed/complaints_prepared.csv
python scripts/run_eval.py --sample 3000 --clusters 12 --seed 42
```

The generator is deterministic for a given seed; `data/source_manifest.csv` records the
generator version, seed, row counts and date. Regenerating replaces the corpus and the
metrics derived from it, so do not mix results from different runs in one report.

## 8. Known data limitations

- Template-generated phrasing is more regular than real citizen language; the
  clustering results measure the pipeline, not field performance.
- Labels come from the generator, not from human annotation. Agreement with them
  (ARI/NMI) is an upper-bound check on structure, not external validity.
- The 71 sub-issues are a project taxonomy, not an official Jharkhand classification.
- Deduplication ground truth covers injected paraphrases only; independent complaints
  about the same issue are explicitly not duplicates.
- Only a single state boundary is bundled, so the UI uses a schematic district grid
  rather than a real choropleth.
